# Dependencias del backend del Módulo RRHH — deliberadamente mínimas.
#
# flask        — sirve la API y el propio .dc.html en el mismo origen (sin CORS)
# requests     — cliente HTTP hacia yunatt.com; su urllib3 es el que permite
#                forzar TLS 1.3, requisito del handshake con yunatt en Windows
# Pillow       — firmas.py recorta y comprime el trazo de la firma antes de
#                incrustarlo en el PDF; fotos.py normaliza las fotos de ficha
# cryptography — google_hoja.py firma el JWT con el que Google concede el
#                token de lectura del formulario de tutores
#
# El almacenamiento usa sqlite3, que viene en la librería estándar de
# Python — no hay servidor de base de datos que instalar ni administrar.

# ATENCIÓN al añadir un `import` de una librería que no sea de la librería
# estándar: si no se declara aquí, en esta máquina no falla nada —tiene
# medio mundo instalado de forma global— y el contenedor se cae al arrancar,
# porque parte de cero y solo instala lo que dice este archivo. Fue
# exactamente lo que pasó con Pillow y cryptography el 03/09/2026: el
# despliegue salía "Success" y el contenedor moría diez veces seguidas con
# `ModuleNotFoundError: No module named 'PIL'`. Lo vigila
# pruebas/prueba_dependencias.py.

# Versiones mínimas, no fijas: este equipo ya tiene flask y requests
# instalados de forma global. Fijar versiones exactas forzaría un
# downgrade que afectaría también al ERP anterior mientras siga en
# producción, porque comparten el mismo Python del sistema.
flask>=3.0
requests>=2.31
Pillow>=10.0
cryptography>=42.0

# Solo para el despliegue en contenedor. En local no hace falta: `py
# backend/app.py` usa el servidor de Flask, que además escucha únicamente en
# 127.0.0.1 —correcto para una máquina de trabajo, inalcanzable dentro de un
# contenedor. Ver Dockerfile y backend/wsgi.py.
gunicorn>=21.2
